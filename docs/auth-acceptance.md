# قبول Auth والوصول

آخر تحقق حي لخط الأساس: 2026-07-29. مصفوفة PBAC المعتمدة في
`docs/permissions.md`.

## الإعداد

- Supabase Auth حقيقي مع تأكيد البريد.
- Site URL للتطوير `http://localhost:3000`.
- Redirects: `/auth/confirm` على `localhost` و`127.0.0.1`.
- الموظف يبدأ `pending_staff_approval`، والعميل يبدأ `client_waiting`.
- MFA وSMS غير داخلين في MVP.
- أول مدير يقرأ من `INITIAL_SUPER_ADMIN_EMAIL` عبر Bootstrap Idempotent.

## نتائج خط الأساس

- نجح تسجيل الموظف والعميل وتأكيد البريد.
- منع الموظف المعلق من البيانات التشغيلية.
- نجح تفعيل الموظف وتحديد الإدارة والمسمى والأدوار.
- نجح دخول الموظف إلى `/workspace` والعميل إلى `/client`.
- نجح Bootstrap مرتين دون تكرار الحساب أو الدور.
- عُطلت حسابات الاختبار بدل حذفها.

## قواعد v2

- العميل لا ينشئ طلب خدمة؛ ينتظر مدير العملاء.
- مدير العملاء ينشئ الطلب ويختار حساب العميل المسجل ويربطه في Transaction واحدة.
- `AccessContext` يحمل `permissions` من `get_my_permissions()`، ويستخدم الدور
  كحاوية فقط.
- مدير الإدارة يرى مشاريع إدارته دون عضوية كل مشروع.
- المشروع والأصل والطلب والقناة والمستند يعاد فحص نطاقها في RLS وRPC.
- اختبار الموظف المؤهل يفصل منفذ الدراسة عن معتمد التقاضي أو التركات.
- Super Admin يملك صلاحيات التدخل، ولا يسند نفسه طرفًا تشغيليًا تلقائيًا.

## الاختبارات

```powershell
npm test
npm run test:e2e
npm run test:auth-live
npm run test:flow-live
```

اختبارات `auth-live` و`flow-live` تنشئ حسابات على المشروع الحي، ثم تعطلها
وتؤرشف بياناتها. لا تشغل تلقائيًا ضمن حزمة Unit اليومية.
