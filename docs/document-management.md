# إدارة المستندات

## التخزين والأنواع

- bucket خاص `legal-documents`، دون Public URLs أو overwrite.
- الحد الأقصى 25MB.
- الأنواع: PDF, DOC, DOCX, XLS, XLSX, JPG, JPEG, PNG.
- لكل مستند سجل ثابت، ولكل إصدار Storage Object مستقل وبصمة SHA-256 وحجم
  وMIME Type ورافع ووقت.
- النسخة الموقعة لعقد أو المنشورة لا تعدل؛ يضاف إصدار جديد.

## الرؤية والنشر

مستوى الرؤية `internal`, `client_visible`, `requires_client_action`.
وحالة النشر `draft`, `awaiting_approval`, `published`, `withdrawn`.

- الارتباط بطلب أو مشروع لا يجعل المستند ظاهرًا للعميل.
- النشر الصريح يحتاج `documents.publish`، والسحب يحتاج `documents.withdraw`.
- `client_visible` وحدها لا تكفي؛ يجب أن تكون الحالة `published`.
- السحب وSoft Delete يخفيان المستند مستقبلًا دون حذف النسخة أو الأثر.
- مستندات الأطراف والورثة لا تكشف لعميل آخر لمجرد اشتراكهم في المشروع.

## العرض والتنزيل

- ينشأ Signed URL عند العرض أو التنزيل فقط ولمدة 300 ثانية.
- الطلب يمر عبر RLS وفحص خادمي للنطاق والرؤية وحالة النشر.
- يسجل `document_access_events` المستخدم والإصدار والوقت وIP وUser Agent والغرض.
- رابط صدر قبل السحب قد يعمل حتى نهاية الخمس دقائق؛ لذلك السحب يسجل فورًا
  ويمنع إنشاء روابط جديدة.

## التدقيق والاحتفاظ

- يسجل Audit الرفع وإنشاء الإصدار وتغيير الرؤية وطلب الاعتماد والنشر والسحب
  والأرشفة وSoft Delete والاستعادة.
- لا يحذف Storage Object في MVP بسبب Soft Delete.
- لا توجد Automatic Purge، وتبقى العقود والعروض والتقارير والنسخ المنشورة.
- الحذف النهائي المستقبلي يحتاج Legal Hold check وصلاحية خاصة وموافقة وسجلًا
  وتنسيقًا بين قاعدة البيانات وStorage.
